The exact O1 rule is as follows. For each accepted eight-byte relocation, refuse any nonempty intersection between its virtual-address span and a nonempty section with both `SHF_ALLOC` and `SHF_EXECINSTR`. Use half-open intervals. A write at `where` occupies `[where, where + 8)`. A section occupies `[section.va, section.va + section.size)`. A one-byte intersection rejects. Exact endpoint adjacency passes this rule. Check virtual-address intersection, not the section name, start address alone, or complete containment.

Build one sorted tuple of executable section intervals at the start of `runtime_relocations`, outside both relocation loops. Include every section type, including NOBITS. The recommended index and query are as follows.



`file_span(where, 8)` has already checked the unsigned end. Do not mask or wrap `where + 8`. An end equal to `2**64` is permitted. The predecessor is sufficient because indexed intervals are disjoint. Every earlier interval ends at or before the selected interval starts. If the selected interval ends before the write, earlier intervals cannot intersect it. An empty index passes.

Do not add a section scan for each relocation. With S sections and R writes, the added O1 work is `O(S log S + R log S)`. Extra storage is `O(S)`. S remains at most 4096 and R at most 262144. F1 also uses an existing index. Each candidate page map uses a binary search, then visits intersecting intervals. For an eight-byte query, there are at most eight nonempty intervals because endpoints are integer byte addresses. With P program headers and the unchanged three granules, added query work is `O(R * 3 * (log P + 8))`. This is a source bound, not a measured time or memory result. No total Python memory guarantee follows from these bounds.
